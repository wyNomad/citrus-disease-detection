# 本轮验证结果

开发环境：Ubuntu 22.04.5 x86_64、Python 3.10、ROS 2 Humble。相机未到手，RK3588 目标板未参与验证。

| 检查 | 结果 | 边界 |
| --- | --- | --- |
| 项目源码语法、XML、Markdown 本地链接 | 通过 | 不校验外部网站可达性 |
| 所有项目 YAML / 驱动清单解析 | 通过 | 具体相机参数需实机确认 |
| 公共包 editable 安装与 sdist / wheel 构建 | 通过 | wheel 仅包含公共 Python 核心，不含 ROS 工作空间 |
| 五个自有 ROS 包与三个 Orbbec 包 | 构建通过 | x86_64 编译，不等于 ARM64 和相机实测 |
| pytest | 33 项通过 | 含 2 项合成 ROS 传输测试 |
| 合成几何示例 | 输出 [0.1, 0.0, 1.0] 米 | 使用人工生成深度，不代表测距精度 |
| 真实 YOLOv8n 离线推理 | Ultralytics 自带 bus.jpg 检出公交车、行人等 6 个目标 | 只验证通用模型，未评估病害模型 |
| 实际 ROS launch，无相机模式 | 真实模型加载，检测/定位节点启动，正常停止 | 无真实取流与测距 |

合成 ROS 测试使用真实发布订阅和假的检测器，校验两种深度编码、多目标、无效深度、采集 Header 及标注图 Header。
另有训练入口测试验证跨工作目录的数据路径解析与产物目录记录，未运行真实训练。
固定驱动应用补丁后的 ob_camera_node.cpp 与原深度工程对应文件逐字节一致。

实际验证环境的关键版本：NumPy 1.26.4、PyYAML 6.0.3、OpenCV wheel 4.11.0.86、Ultralytics 8.4.140、PyTorch 2.14.0+cu130（实际使用 CPU）、pytest 8.4.2、setuptools 79.0.1。
本环境复用了笔记本已有的 PyTorch 和 ROS 系统包，不是全新操作系统的无人值守安装验收。

未验证：真实病害数据训练与效果、Gemini 305 取流/对齐/深度单位/定位精度、ARM64 驱动运行、RKNN NPU 后端、帧率与稳定性。
